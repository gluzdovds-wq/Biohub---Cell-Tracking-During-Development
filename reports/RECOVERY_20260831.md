## Incident

EXP094–097 (`55908273`, `55908462`, `55908629`, `55908683`) failed with
Kaggle `error_description`: `submission file with incorrect format`. All four
have `status=COMPLETE`, empty scores, and `total_bytes=0`; this means failure,
not delayed scoring.

Root cause: `kaggle_notebooks/exp094_097_coordinate_batch/coordinate_batch.py`
discovers frozen parent `submission.csv` files under `/kaggle/input` by public
artifact SHA and emits blends of those four public datasets. It never reads the
runtime competition test set. Public downloads therefore passed schema, graph,
hash, and dataset-count checks, while the hidden rerun emitted public dataset
IDs instead of hidden-test predictions and was rejected.

The cascade happened because the post-submit check used only status and score.
After EXP094 became COMPLETE with an empty score, the agent recorded “score not
populated” without reading `error_description`, then submitted EXP095–097.
The parent EXP093 (`55907915`) was still PENDING, so the child promotion gate
was also violated. The five daily slots are exhausted.

## Recovery controls

`AGENTS.md` now defines the mandatory protocol. The guarded helper
`scripts/submit_code_file_once.py` rejects frozen-public-submission wrappers,
requires source SHA and auditable runtime competition discovery, blocks after
a recorded API error or a terminal COMPLETE result without a score, and
permits another independently pre-registered and audited candidate while an
earlier submission is PENDING. A scored-parent gate is not required. Tests are
in `tests/test_submit_code_file_once.py`. This batching-policy correction was
authorized by the user on 2026-09-01.

The August 31 recovery stop was satisfied after EXP093 reached COMPLETE with a
score and the failed wrappers were recorded. Current submission authorization
